# chillanel 전면 개편 로드맵 (UI/UX · SEO · AEO)

> 이 문서는 **마스터 로드맵**입니다. 각 Phase를 실행할 때 해당 Phase만의 상세 구현 플랜(태스크 단위, 코드 포함)을 따로 작성합니다. 이 문서 자체는 아무것도 구현하지 않습니다.

**목표:** "들어오자마자 있고 싶은" 프리미엄 스파 가이드. **사진 없이, 100% 무료로** 지금의 텍스트+그라디언트 디렉토리를 리뷰 데이터 시각화 기반의 진짜 제품으로.

**방향 확정 (2026-07-24 유저 결정):** 사진 파이프라인 없음. 마사지샵 업종 특성상 사진이 필수가 아니라는 판단 + 100% 무료 유지. 대신 **리뷰 데이터 시각화**로 차별화 — 우리가 갖고 있는 12,569개 리뷰의 실제 내용(평점 분포, 자주 언급되는 키워드/테마, 테라피스트 언급 빈도)을 그래픽으로 보여주는 것 자체가 사진보다 강한 차별화포인트(경쟁 사이트 중 이걸 하는 곳이 없음).

---

## 진단 — 왜 계속 허접해 보이는가 (솔직한 원인 분석)

세 번의 UI 패스(색/폰트 → 밀도/신뢰 배지 → 레이아웃 재구성)를 했는데도 허접해 보이는 이유는 스타일링 문제가 아니라 **구조적 결핍** 때문:

1. **콘텐츠가 다 "메타데이터"뿐, "인사이트"가 없음.** 이름/주소/평점/리뷰수는 Google Maps에도 다 있는 정보. 우리만 가진 건 12,569개 리뷰 "본문"인데 지금은 그중 딱 하나(테라피스트 이름)만 뽑아 쓰고 나머진 그냥 리스트로 보여줌. 리뷰를 분석해서 얻은 진짜 통찰(어떤 서비스가 많이 언급되는지, 평점이 왜 높은지, 어떤 분위기인지)을 시각화하지 않으면 "구글맵 미러링 사이트"로 보임.
2. **탐색 구조가 1단계뿐.** 홈 → 방콕(734개 정렬 리스트) → 상세. 지역(스쿰빗/실롬/통로)도, 카테고리(타이마사지/발마사지/오일)도, 검색도, 필터도 없음.
3. **페이지당 고유 콘텐츠가 얇음.** 상세 페이지 = 이름+주소+리뷰 10개 나열. SEO 관점에서 2,200페이지가 사실상 같은 템플릿의 얇은 변형(thin content) — 구글이 제일 싫어하는 패턴.
4. **나(Claude)의 시각 피드백 루프 부재.** 이 세션엔 스크린샷 도구가 없어서 배포 결과물을 한 번도 눈으로 확인 못 하고 HTML 문자열 검증만 했음.

**결론: Phase 0(기반)을 건너뛰고 UI만 또 고치면 네 번째도 허접합니다.**

## Phase 0 — 기반 (이거 없이는 다음 단계 무의미)

### 0-1. 시각 피드백 루프 (Claude용 눈) — 최우선
- Playwright 스크린샷 스크립트(`chillanel/scripts/screenshot.mjs`) 추가: 주요 페이지를 데스크톱/모바일 뷰포트로 캡처 → 파일로 저장 → 내가 Read로 직접 봄.
- 이후 모든 디자인 변경은 **캡처 → 확인 → 수정** 루프로. "배포했으니 봐줘"를 반복하지 않게 됨.

### 0-2. 리뷰 마이닝 확장 (진짜 콘텐츠 원료 생산 — 이번 개편의 핵심)
`extract-therapists.mjs`와 같은 무료·정규식 기반 방식으로 `build-data.mjs`에 추출기 추가. 전부 로컬 연산, API 비용 없음:

- **서비스 테마 빈도**: 리뷰에서 "foot massage", "oil massage", "Thai massage", "aroma", "deep tissue", "hot stone" 등 키워드/동의어 사전 매칭 → 매장별 `{ label, count }[]`. 카테고리 페이지·필터·태그 구름의 데이터 소스.
- **분위기/품질 키워드 빈도**: "clean"/"quiet"/"relaxing"/"strong pressure"/"gentle"/"friendly"/"good value"/"walk-in ok" 등 → 매장별 상위 키워드. 카드 한 줄 요약 + 시각화 태그.
- **평점 분포**: 리뷰 배열(`place.reviews[].rating`)에서 1~5점 개수 히스토그램 계산 — 이미 있는 데이터라 추출기 불필요, `build-data.mjs`에서 집계만.
- **가격 언급**: "300 baht", "฿500" 정규식 → 대략적 가격대. (`price_level` CSV 필드가 16/734개만 채워져 있어 이걸로 보완)
- **지역 클러스터링**: lat/lng → 방콕 주요 지역(Sukhumvit/Silom/Sathorn/Thonglor/Khaosan 등) 매핑 테이블로 `district` 필드 생성. 정적 좌표 범위 매핑이라 무료·즉시.
- **도시/지역 레벨 집계**: 위 항목들을 모든 매장에 걸쳐 합산 → "방콕 리뷰어들이 가장 많이 말하는 것" 사이트 전역 태그 구름 데이터.

## Phase 1 — UI/UX 전면 재구축 (리뷰 데이터 시각화 중심, 사진 없음)

디자인 방향은 유지(프리미엄 스파 무드: ink/teal/gold + Fraunces) — 사진 대신 **데이터 시각화가 사진의 역할**(스캔성·신뢰도·차별화)을 대신함.

- **매장 카드 v3**: 사진 헤더 자리에 미니 평점 분포 막대(★5→★1, 5개 얇은 바) + 상위 테마 태그 2~3개(pill). 지금의 그라디언트 헤더는 유지하되 그 위에 데이터 오버레이.
- **상세 페이지 v2**:
  - 평점 분포 막대차트 (현재 별점 숫자만 있는 곳에 시각적 히스토그램 추가)
  - "리뷰어들이 자주 말하는 것" 태그 구름 (빈도 비례 크기)
  - 서비스 테마 배지 행 (발마사지/오일/타이 등)
  - 근처 매장 3개(지역 클러스터 기반 내부 링크)
- **홈/도시 페이지**: 사이트 전역 태그 구름 섹션 추가("방콕 리뷰 12,569개에서 가장 많이 언급된 것") — 순수 데이터 시각화라 매력 있고 사진 불필요, AEO에도 재사용 가능
- **지역 페이지** (`/[lang]/area/[district]`): 그 지역 매장 리스트 + 지역 집계 태그 구름. 지도는 생략(무료 우선 원칙 — "구글맵에서 보기" 외부 링크로 충분, 이미 존재)
- **카테고리 페이지** (`/[lang]/category/[service]`): 발마사지/오일/타이/아로마별 리스트, 테마 빈도 기반
- **필터/정렬 바**: 가격대, 평점, 테라피스트 언급 여부, 서비스 테마, 정렬(평점/리뷰수)
- **검색**: 이름/지역 클라이언트 사이드 검색 (734개면 인덱스 JSON 하나로 충분, 서버 불필요 = SSG 유지)

## Phase 2 — SEO 프로그래매틱 확장

- **지역 × 카테고리 매트릭스 페이지**: "Foot massage in Sukhumvit" 같은 롱테일 (지역 ~10 × 카테고리 ~6 × 언어 3 = ~180페이지, 각각 실데이터 리스트 + 집계 시각화라 thin 아님)
- **상세 페이지 고유 텍스트**: 리뷰 마이닝 결과(테마·키워드·가격대)로 매장마다 다른 요약 문단 자동 생성 (템플릿+실데이터 조합, 언어별, 무료) — thin content 탈출의 핵심
- **내부 링크망**: 상세→근처 매장(지역 클러스터), 상세→지역/카테고리, 지역↔카테고리 교차
- **메타 강화**: 매장별 고유 description(자동 요약문 재사용), Review/AggregateRating 스키마에 평점 분포 반영
- **sitemap 우선순위 재조정** + 지역/카테고리 페이지 추가

## Phase 3 — AEO 확장

- **"Best X in Y" 페이지**: "Best foot massage in Sukhumvit" 등 — AI 답변엔진이 그대로 인용할 수 있는 리스트형 + 근거(평점 분포·리뷰수·인용구) 포함
- **FAQ 매트릭스**: 지역별·카테고리별 FAQ, FAQPage 스키마 유지
- **가이드 확장**: 현 3편 → 8~10편 (가격 가이드는 리뷰 가격 언급 실데이터 기반으로 자동 생성 가능), HowTo 스키마
- **테라피스트 언급 + 리뷰 테마 데이터의 AEO 활용**: "방콕에서 조용한 마사지샵은?" "발마사지 잘하는 곳?" 같은 질문에 우리 집계 데이터로 직접 답 — 이 각도의 콘텐츠 페이지

## Phase 4 — 운영/자동화 정리

- `refresh-and-deploy.mjs`가 리뷰 마이닝(테마/키워드/지역 집계) 포함하도록 확장 — 이미 `build-data.mjs`에서 처리되므로 자연히 포함됨, 검증만 추가
- 스크래핑 완료 시(그리드 ETA ~2일) 리뷰 스크래퍼 재개 → 데이터 풀 확대 → 재빌드 자동 배포
- `chillanel.com` 도메인: 현재 vamoss2 프로젝트에 미연결 (Hostinger DNS도 미변경) — 연결 시점 결정 필요

## 유저 결정 필요 사항 (남은 것)

1. **chillanel.com 연결 시점** — 개편 완료 후 vs 지금
2. **키워드/테마 사전의 언어 범위** — en 리뷰가 절대다수일 가능성 높음(구글 리뷰 특성상). th/ko 리뷰도 유의미한 양이 있는지 확인 필요 → Phase 0-2 착수 시 실제 데이터로 언어별 리뷰 분포부터 체크하고 사전 설계

## 실행 순서 요약

```
Phase 0 (기반)          : 0-1 스크린샷 도구 → 0-2 리뷰 마이닝(테마/키워드/평점분포/지역클러스터)
Phase 1 (UI 재구축)     : 데이터 시각화 컴포넌트로 카드/상세/홈/지역/카테고리 재구축
Phase 2 (SEO)           : Phase 0-2 산출물(지역/테마 태그) 위에서 매트릭스 페이지 생성
Phase 3 (AEO)           : Phase 2 페이지 구조 위에서 Best-X-in-Y, FAQ 매트릭스
Phase 4 (운영)          : 마지막 배선
```

전부 무료(로컬 정규식/정적 매핑 연산, 외부 API 없음). 각 Phase 착수 시 상세 구현 플랜(태스크·코드·검증 단계 포함)을 별도 작성 → 승인 → 서브에이전트 실행.

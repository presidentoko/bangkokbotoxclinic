# chillanel 전면 개편 로드맵 (UI/UX · SEO · AEO)

> 이 문서는 **마스터 로드맵**입니다. 각 Phase를 실행할 때 해당 Phase만의 상세 구현 플랜(태스크 단위, 코드 포함)을 따로 작성합니다. 이 문서 자체는 아무것도 구현하지 않습니다.

**목표:** "들어오자마자 있고 싶은" 프리미엄 스파 가이드. 지금의 텍스트+그라디언트 디렉토리를 사진·콘텐츠·탐색 구조가 있는 진짜 제품으로.

---

## 진단 — 왜 계속 허접해 보이는가 (솔직한 원인 분석)

세 번의 UI 패스(색/폰트 → 밀도/신뢰 배지 → 레이아웃 재구성)를 했는데도 허접해 보이는 이유는 스타일링 문제가 아니라 **구조적 결핍** 때문:

1. **사진이 0장.** 프리미엄 스파 사이트처럼 보이는 사이트들(thaigle 포함)의 공통점은 실제 매장 사진. 우리 스크래퍼는 photo URL을 아예 수집한 적이 없음 (`clinics.csv`에 필드 자체가 없음). 그라디언트 카드로는 이 격차를 못 메꿈 — 확인 결과 CSV의 `editorial_summary`(4/734), `price_level`(16/734)도 거의 비어 있어서 "이미 있는 데이터 활용"으로는 해결 불가.
2. **탐색 구조가 1단계뿐.** 홈 → 방콕(734개 정렬 리스트) → 상세. 지역(스쿰빗/실롬/통로)도, 카테고리(타이마사지/발마사지/오일)도, 검색도, 필터도 없음. 유저는 "내 호텔 근처 발마사지"를 찾으러 오는데 우리는 평점순 90개를 던져줌.
3. **페이지당 고유 콘텐츠가 얇음.** 상세 페이지 = 이름+주소+리뷰 10개 나열. 12,569개 리뷰를 갖고 있으면서 요약도, 테마 추출도, 가격 언급 추출도 안 함. SEO 관점에서 2,200페이지가 사실상 같은 템플릿의 얇은 변형(thin content) — 구글이 제일 싫어하는 패턴.
4. **나(Claude)의 시각 피드백 루프 부재.** 이 세션엔 스크린샷 도구가 없어서 배포 결과물을 한 번도 눈으로 확인 못 하고 HTML 문자열 검증만 했음. 디자인을 장님 상태로 반복한 것 — 도구를 먼저 깔지 않으면 다음 패스도 같은 실패를 반복함.

**결론: Phase 0(기반)을 건너뛰고 UI만 또 고치면 네 번째도 허접합니다.**

## Phase 0 — 기반 (이거 없이는 다음 단계 무의미)

### 0-1. 사진 파이프라인 ⚠️ 최우선, 유저 결정 필요
| 옵션 | 방법 | 비용 | 품질 |
|---|---|---|---|
| **A. 스크래퍼 확장 (추천)** | `bangkok_clinics/scraper_grid.py`가 place 패널에서 사진 URL(`lh3.googleusercontent.com/...`)도 긁도록 수정. thaigle이 이미 이 방식(`photos_sample`) — 검증된 패턴 | 무료 | 매장당 3~6장, 충분 |
| B. Google Places API Photos | place_id로 공식 API 호출 | 유료 (사진 1천장당 ~$7) | 최고 품질, 안정적 URL |
| C. 하이브리드 | 상위 100개만 API, 나머지 스크랩 | 소액 | 절충 |

- A 선택 시: 스크래퍼 수정 → **지금 돌고 있는 grid가 끝난 뒤** 사진 전용 보충 패스(place_id 목록 재방문)로 수집. 라이브 스크래핑 중단 없음.
- `next.config.ts`의 `remotePatterns`는 이미 `lh3.googleusercontent.com` 허용 — UI 쪽은 준비돼 있음.
- thaigle의 `CardImage.tsx` 패턴 이식: `next/image` + `onError` 시 그라디언트 폴백 (사진 없는 매장도 안 깨짐).

### 0-2. 시각 피드백 루프 (Claude용 눈)
- Playwright 스크린샷 스크립트(`chillanel/scripts/screenshot.mjs`) 추가: 주요 페이지를 데스크톱/모바일 뷰포트로 캡처 → 파일로 저장 → 내가 Read로 직접 봄.
- 이후 모든 디자인 변경은 **캡처 → 확인 → 수정** 루프로. "배포했으니 봐줘"를 반복하지 않게 됨.

### 0-3. 리뷰 마이닝 확장 (콘텐츠 원료 생산)
`extract-therapists.mjs`와 같은 방식으로 `build-data.mjs`에 추출기 추가:
- **서비스 테마**: 리뷰에서 "foot massage", "oil massage", "aroma", "hot stone" 등 언급 빈도 → 매장별 서비스 태그 (카테고리 페이지·필터의 데이터 소스)
- **가격 언급**: "300 baht", "฿500" 패턴 → 대략적 가격대 표시 (`price_level` 공백 메꿈)
- **분위기 키워드**: "clean", "quiet", "luxurious" 상위 키워드 → 카드/상세의 한 줄 요약
- **지역 클러스터링**: lat/lng → 방콕 주요 지역(Sukhumvit, Silom, Sathorn, Thonglor, Khaosan 등) 매핑 테이블 → district 필드 생성

## Phase 1 — UI/UX 전면 재구축 (사진 확보 후)

- **홈**: 사진 기반 히어로(베스트 매장 사진 콜라주 or 풀블리드 1장), 지역별 바로가기(사진 타일), 카테고리 바로가기, 베스트 벤토(사진 카드), 리뷰 인용 레일 유지
- **매장 카드 v3**: 사진 헤더(폴백=현 그라디언트), 평점/리뷰수/가격대/서비스 태그/테라피스트 배지
- **지역 페이지** (`/[lang]/area/[district]`): 지도 미리보기(정적 이미지 or 경량 지도), 그 지역 매장 리스트, 지역 소개문
- **카테고리 페이지** (`/[lang]/category/[service]`): 발마사지/오일/타이/아로마별 리스트
- **필터/정렬 바** (도시·지역·카테고리 페이지 공통): 가격대, 평점, 테라피스트 언급 여부, 정렬(평점/리뷰수)
- **검색**: 이름/지역 클라이언트 사이드 검색 (734개면 인덱스 JSON 하나로 충분, 서버 불필요 = SSG 유지)
- **상세 페이지 v2**: 사진 갤러리, 서비스 태그, 가격 언급 요약, 리뷰 테마 요약("리뷰어들이 자주 말하는 것"), 근처 매장 3개(내부 링크), 같은 지역/카테고리 링크
- 디자인 방향은 유지(프리미엄 스파 무드: ink/teal/gold + Fraunces) — 문제는 방향이 아니라 재료였음

## Phase 2 — SEO 프로그래매틱 확장

- **지역 × 카테고리 매트릭스 페이지**: "Foot massage in Sukhumvit" 같은 롱테일 (지역 ~10 × 카테고리 ~6 × 언어 3 = ~180페이지, 각각 실데이터 리스트라 thin 아님)
- **상세 페이지 고유 텍스트**: 리뷰 마이닝 결과로 매장마다 다른 요약 문단 자동 생성 (템플릿+실데이터 조합, 언어별) — thin content 탈출의 핵심
- **내부 링크망**: 상세→근처 매장, 상세→지역/카테고리, 지역↔카테고리 교차 — 지금은 리프 페이지 2,200개가 고아 상태에 가까움
- **메타 강화**: 매장별 고유 description(요약문 재사용), Review/AggregateRating 스키마 확장, ImageObject(사진 확보 후)
- **sitemap 우선순위 재조정** + 지역/카테고리 페이지 추가

## Phase 3 — AEO 확장

- **"Best X in Y" 페이지**: "Best foot massage in Sukhumvit" 등 — AI 답변엔진이 그대로 인용할 수 있는 리스트형 + 근거(평점·리뷰수·인용구) 포함
- **FAQ 매트릭스**: 지역별·카테고리별 FAQ (현재 홈/도시 2종 → 페이지 타입별 맞춤 질문), FAQPage 스키마 유지
- **가이드 확장**: 현 3편 → 가격 가이드(리뷰 가격 언급 실데이터 기반), 에티켓/팁, 지역별 가이드 등 8~10편, HowTo 스키마
- **테라피스트 언급 데이터의 AEO 활용**: "어느 마사지샵에서 테라피스트를 지명할 수 있나" 류 질문에 우리만 답할 수 있음 — 이 각도의 콘텐츠 페이지 1~2개

## Phase 4 — 운영/자동화 정리

- `refresh-and-deploy.mjs`가 사진 보충 패스·리뷰 마이닝 포함하도록 확장
- 스크래핑 완료 시(그리드 ETA ~2일) 리뷰 스크래퍼 재개 → 데이터 풀 확대 → 재빌드 자동 배포
- `chillanel.com` 도메인: 현재 vamoss2 프로젝트에 미연결 (Hostinger DNS도 미변경) — 연결 시점 결정 필요

## 유저 결정 필요 사항

1. **사진 수집 방식** (0-1의 A/B/C) — A(스크래퍼 확장) 추천
2. **지도 표시** — 정적 이미지(무료·SSG 유지) vs 인터랙티브 지도(외부 스크립트·성능 비용) vs 생략
3. **상세 페이지 자동 요약문** — 템플릿+실데이터 조합(무료·즉시) vs LLM 생성(비용·품질↑) 
4. **chillanel.com 연결 시점** — 개편 완료 후 vs 지금

## 실행 순서 요약

```
Phase 0 (기반)          : 0-2 스크린샷 도구 → 0-3 리뷰 마이닝 → 0-1 사진 (그리드 완료 대기와 병행)
Phase 1 (UI 재구축)     : 사진 들어온 뒤 — 그 전에 하면 또 그라디언트 신세
Phase 2 (SEO)           : Phase 0-3 산출물(지역/서비스 태그) 위에서
Phase 3 (AEO)           : Phase 2 페이지 구조 위에서
Phase 4 (운영)          : 마지막 배선
```

각 Phase 착수 시 상세 구현 플랜(태스크·코드·검증 단계 포함)을 별도 작성 → 승인 → 서브에이전트 실행.
